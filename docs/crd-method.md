# CRD extraction decision log

The source set was treated in Extract mode. The prototype brief explicitly authorizes a reusable capability projection because multiple existing Valuatum products and a new integration realization are the intended consumers.

Each inventory candidate was tested independently for understandable purpose, meaningful invocation, determinable success/failure, and loss of purpose if split further. Company search, profile retrieval, financial retrieval, risk assessment, risk explanation, report generation, valuation, valuation explanation, listed-company analysis, equity-report generation, comparison, and delivery each passed independently and therefore remain separate Capability MLEs.

The proposed decision brief also passes independently: its outcome is not merely the sum of raw calls, but a decision-contextualized brief with uncertainties and next questions. It composes other capabilities without absorbing them.

Endpoints, MCP tools, pages, schemas, and datasets failed the capability test because they are technical surfaces or primitives. They are mapped as realizations or shared elements instead.

Unknowns are preserved in each CRD. Public product behavior is not used to infer private architecture, formulas, authorization, data vendors, or operational controls.
